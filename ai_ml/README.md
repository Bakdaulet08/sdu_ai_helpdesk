# AI/ML: индексация базы знаний

Реализован этап 2: **CSV → вопрос → multilingual-e5-small → pgvector**,
и retrieval по FAQ с порогом (этап 3).
Ответ хранится вместе с ID, языком, исходной категорией и строкой источника.
Размер вектора — 384. Генерация GPT/Gemini добавлена отдельным этапом ниже.
Модерация и выбор самого залайканного ответа из живого форума пока не входят.
FAQ — отдельный источник, не форум.

## Быстрый запуск в Windows CMD

Все команды ниже выполняются из `ai_ml`:

```bat
cd /d C:\Users\tolai\sdu_ai_helpdesk\ai_ml
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
.venv\Scripts\python.exe -m kb.cli prepare
```

Если `.venv` уже создано, повторять создание не нужно. Если `.env` уже есть,
редактируйте его, а не перезаписывайте. Python 3.11/3.12 рекомендуется.
Файл `requiremets.txt` оставлен как совместимый указатель на `requirements.txt`.

## Данные

Исходный файл: `data/raw/faq.csv`. Используется подготовленный CSV, а не повторный
разбор Excel старыми скриптами. `prepare` не требует сторонних библиотек.

Обязательные колонки: `id,question,answer,language,status`.
Дополнительно поддерживаются `category_original,source_row,source_date,faq_id,review_notes`.
Допускаются статусы `needs_review`, `content_review`, `verified`: автор подтвердил ответы.
`alignment_review` и пустые ответы исключаются. Короткие ответы не удаляются.
Повторы вопросов с разными ID сохраняются. Повторяющийся ID вызывает ошибку.
Категории пока сохраняются в исходном виде; смешанные категории не переименовываются автоматически.

Результат: `data/processed/qa_clean.jsonl`, `data/processed/index_report.json`,
`data/rejected/faq_excluded.jsonl`. Для текущего файла: 735 пар, 234 пустых ответа,
36 неоднозначных сопоставлений. Эти генерируемые файлы не коммитятся.

## Проверить embeddings без PostgreSQL

```bat
.venv\Scripts\python.exe -m kb.cli index --local-only
```

При первом запуске скачивается открытая модель. Требуются интернет, место на диске
и время на CPU. Вызовов платного API нет, но локальные вычисления расходуют ресурсы.
Модель сохраняется в локальном кэше `ai_ml/.cache/huggingface`.
Создаются `data/index/embeddings.npy`, `records.json`, `metadata.json`.
Это локальные артефакты; PostgreSQL эта команда не изменяет.

Индексируется только вопрос с префиксом `passage: `. При поиске используется
`query: `. Префиксы нужны и для ru/kk/en. Длинные вопросы не обрезаются молча —
команда сообщает об превышении лимита модели.

## PostgreSQL + pgvector

В корневом Docker Compose используется `postgres:16-alpine`; это не установка
pgvector. Для изолированной проверки добавлен `compose.kb.yml` с отдельным томом
и портом 55432. Он не подключается к тому backend-базы.
Нужен установленный и запущенный Docker Desktop:

```bat
docker compose -f compose.kb.yml up -d --wait
.venv\Scripts\python.exe -m kb.cli init-db
.venv\Scripts\python.exe -m kb.cli index
.venv\Scripts\python.exe -m kb.cli search --question "Как получить справку об обучении?" --top-k 3
```

Для существующей командной базы укажите её URL в `KB_DATABASE_URL` в `ai_ml/.env`.
Сначала backend-разработчик должен установить серверное расширение pgvector.
Команда `init-db` включает `vector` и создаёт только таблицы `ai_kb_datasets` и
`ai_kb_entries`; для включения расширения нужны соответствующие права БД.
Корневой `.env` намеренно не читается: команда не подключается к backend-БД случайно.
Реальные пароли и `.env` не добавляйте в Git.

Поиск точный, через cosine distance (`<=>`), без приближённого HNSW-индекса:
для 735 FAQ этого достаточно. `score = 1 - cosine_distance`, не вероятность
правильности. Команда поиска показывает ближайшие записи без порога и без LLM.
Порог надо отдельно подобрать на тестовых вопросах, включая вопросы вне базы.

## Retrieval с порогом: ответ либо отсутствие совпадения

После создания индекса выполните:

```bat
.venv\Scripts\python.exe -m kb.cli retrieve --question "Как получить справку об обучении?" --threshold 0.80
```

Команда кодирует вопрос той же E5-моделью с префиксом `query:`, ищет top-1 в
pgvector и сравнивает cosine similarity с порогом **без округления**.
При `score >= threshold` возвращается исходный ответ без генерации или перевода.
При меньшем score: `status=not_found`, `answer=null`, `source=null`.
Порог берётся из `--threshold`, иначе из `KB_MIN_SIMILARITY`, иначе 0.80.
Это стартовое значение, не измеренная граница качества и не 80% уверенности.
`search` по-прежнему служит диагностикой top-k без порога.

Структура успешного результата:

```json
{
  "status": "matched",
  "matched": true,
  "dataset": "faq",
  "threshold": 0.8,
  "score": 0.87,
  "answer": "Исходный ответ из найденной записи",
  "source": {
    "id": "ID записи",
    "question": "Вопрос из базы",
    "category": "portal",
    "language": "ru",
    "source_row": "12"
  }
}
```

Это иллюстрация контракта, а не реальный результат измерения. Для пустой выдачи
score будет null; для выдачи ниже порога score остаётся для диагностики.
Недоступность БД, отсутствующий индекс и ошибка модели поднимают исключение,
а не маскируются как `not_found`.

Вызов из будущего Python API (модель создать один раз при старте процесса):

```python
from kb.embedding import E5
from kb.retrieval import postgres_retriever

encoder = E5(device="cpu")
retriever = postgres_retriever(database_url, encoder, threshold=0.80, dataset="faq")
result = retriever.retrieve(student_question)
```

Сейчас source — FAQ. Здесь **нет выбора ответа форума по лайкам**: для этого нужно
индексировать ID тредов и получать актуальный лучший ответ из backend форума.
API-обёртка относится к следующему этапу.

## Генерация GPT / Gemini (этап 4)

В `ai_ml/.env` добавьте:

```dotenv
LLM_PROVIDER=openai
LLM_MODEL=имя_доступной_вам_модели
LLM_API_KEY=ваш_ключ
LLM_TIMEOUT_SECONDS=60
KB_CONTEXT_FILE=config/university_context.txt
```

Для Gemini поменяйте `LLM_PROVIDER=gemini`, модель и ключ на данные Google AI Studio.
Используется Chat Completions с JSON object output; модель должна поддерживать
этот интерфейс. Ключи провайдеров не взаимозаменяемы. Дополнительный SDK не нужен:
HTTP-клиент использует стандартную библиотеку Python. Запрос и найденный ответ
передаются выбранному внешнему провайдеру.

После настройки индекса и `.env`, в CMD:

```bat
.venv\Scripts\python.exe -m kb.cli generate --question "Как получить справку об обучении?" --language ru --threshold 0.80
```

Результат содержит `status`, `forum_answer`, `ai_explanation`, `source`,
`source_type`, `basis`, `reason`, `retrieval_score` и `language`.

- Совпадение: `forum_answer` дословно копируется из индекса, LLM создаёт только
  `ai_explanation`. Исходный ответ остаётся на исходном языке, пояснение — на ru/kk/en.
- Нет совпадения: `forum_answer=null`. Допускается общий совет по учёбе либо ответ
  из явно заданных фактов `config/university_context.txt`. Этот файл сейчас содержит
  только название университета и назначение сервиса. Дополняйте его проверенными фактами.
- Неуверенность (`can_answer=false`): `status=fallback`, `ai_explanation` строго
  «Обратитесь в деканат.» для ru, с фиксированными переводами для kk/en.
  Найденный исходный ответ, если он был, сохраняется отдельно.
- Некорректный JSON: тот же фиксированный fallback, `reason=invalid_model_output`.
- Ошибка сети, ключа, лимита API или БД: исключение, не маскируем как отсутствие знаний.
  Будущая API-обёртка должна преобразовать такие ошибки в подходящий HTTP-статус.

`forum_answer` — имя поля по контракту команды. Пока данные взяты из FAQ,
`source_type=faq`; frontend должен показывать «Ответ из базы знаний», а не выдавать
его за самый залайканный ответ сообщества.

Промпт запрещает выдумывать университетские цены, сроки, контакты и правила.
Это ограничение промпта, а не доказательство корректности: самооценка модели
`can_answer` не является калиброванной уверенностью. Требуется проверка на реальных
вопросах, особенно на вопросах вне базы и на противоречиях. Код проверяет формат
и допустимость заявленного источника, но не семантическую истинность пояснения.

Документация API: [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create),
[Gemini OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai).

Проверка этапа 4: тесты используют подставные ответы API, без платных вызовов.
Реальные вызовы GPT/Gemini пока не выполнялись: модель и API-ключ не настроены.

## Замена CSV завтра

Для полной новой версии замените `data/raw/faq.csv`, сохраните прежние ID для
исправленных вопросов и выполните `index` снова. Модель пересчитает векторы.
В одной транзакции заменяется только набор `--dataset faq`: старые записи удаляются,

Если новый CSV содержит только дополнения, сначала объедините его с существующим:
`index` принимает полную версию набора, а не инкрементальный файл.

## Этап 5: API для backend

`POST /generate-answer` вызывает retrieval и генерацию. Go-backend и admin-дашборд
не изменены: backend должен вызывать этот внутренний ML-сервис по HTTP.
Модель загружается один раз при запуске через
[FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/).

Из папки `ai_ml`, в CMD:

```cmd
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn kb.api:app --host 127.0.0.1 --port 8001 --workers 1
```

Предварительно настройте `.env`, загрузите E5 и заполните индекс pgvector.
Документация и пробный запрос: http://127.0.0.1:8001/docs
OpenAPI: http://127.0.0.1:8001/openapi.json

Тело запроса, Content-Type: application/json:

```json
{"question":"Как получить справку об обучении?","language":"ru"}
```

Вопрос — 1–2000 символов, не только пробелы; language — ru/kk/en (по умолчанию ru).
Лишние поля запрещены. HTTP 200 возвращает request_id, status (answered/fallback),
forum_answer, ai_explanation, language, basis, reason, source, source_type, retrieval_score.
Исходный forum_answer сохраняется на языке базы; language задаёт язык пояснения.

Ошибки: JSON с request_id, status=error и error:
- 502 llm_unavailable: сбой LLM;
- 503 pipeline_unavailable: ошибка retrieval, индекса или внутреннего результата;
- 503 logging_unavailable: журнал недоступен, ответ не возвращается;
- 503 service_busy: уже выполняется запрос, повторите позже.
Некорректный JSON, язык или вопрос возвращают 422 со стандартным detail FastAPI.

Один процесс выполняет один ML-запрос за раз; остальные получают 503 без очереди.
Это внутренний сервис без пользовательской авторизации/CORS/rate limiting.
Запускайте за backend, проверяющим пользователя. Команда слушает только localhost.
Для разных серверов или контейнеров отдельно настройте приватную сеть.

### Журнал запросов

KB_REQUEST_LOG задаёт SQLite-файл, по умолчанию data/logs/requests.sqlite3.
Путь относительно ai_ml, каталог исключён из Git. Таблица answer_requests хранит
request_id, created_at (UTC), question, language, status, http_status, duration_ms,
response_json. Перед генерацией записывается processing, затем итоговый ответ.
При аварийном завершении процесса запись может остаться processing.
Запросы с ошибкой валидации 422 не сохраняются. Ключи и тексты исключений не пишутся.
Журнал содержит тексты студентов; доступ предоставляйте сервису и администраторам.
Это локальный журнал прототипа, ещё не интеграция с БД Go-backend или story 19.

SQL для будущего дашборда и поиска вопросов без ответа:

```sql
SELECT request_id, created_at, question, language, status, duration_ms, response_json
FROM answer_requests ORDER BY created_at DESC LIMIT 100;
SELECT question, language, response_json FROM answer_requests WHERE status = 'fallback';
```

Новые вопросы не становятся проверенными FAQ автоматически: ответ добавляет человек.
Реальный API-ключ храните только в .env; шаблон .env.example оставляйте без секретов.

Тесты используют временную SQLite и заглушку AnswerService без платных запросов:

```cmd
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m unittest discover -s tests -v
```


## Этап 6: модерация текста форума

`kb/moderation.py`: отдельный zero-shot классификатор через тот же ChatClient и
LLM_PROVIDER/LLM_MODEL/LLM_API_KEY из .env. Retrieval для классификации не вызывается.
Поддержка ru/kk/en и смешанного текста задана в промпте, качество требует оценки.

`POST /moderate`, Content-Type: application/json:

```json
{"text":"Как получить справку об обучении?"}
```

Пример успешного решения (не результат реального вызова):

```json
{"request_id":"...","decision":"allow","publish_allowed":true,"categories":[],"reason":"ok","policy_version":"toxicity-v1"}
```

Решения: allow — публикация разрешена; block — нарушение; review — ручная проверка.
Категории: harassment, hate, threat, sexual_harassment.
Промпт разрешает критику университета, несогласие и обращение за помощью при травле.
Мат сам по себе не блокирует сообщение. Неоднозначный контекст направляется на review.
Невалидный ответ модели даёт review/invalid_model_output. Сбой LLM — HTTP 502,
другая ошибка/занятый классификатор — HTTP 503, всегда publish_allowed=false.
Невалидное тело — HTTP 422. Допустим текст 1–10000 символов, не только пробелы.
Неизвестный результат, таймаут и любой не-200 backend не должен считать разрешением.

### Подключение коллегой в Go-backend

В internal/handlers/forum.go перед Store.CreateThread и Store.CreateComment вызовите
ML-сервис /moderate. Для темы передавайте заголовок и текст вместе, для комментария
его текст. Проверяйте также редактирование перед сохранением. Публикуйте только при
HTTP 200, decision=allow И publish_allowed=true. При block предложите изменить текст;
при review не публикуйте и отправьте на ручную проверку. При сетевой ошибке предложите
повторить позже. Если текст превышает лимит, не обрезайте его: отклоните или согласуйте
лимит с ML-сервисом. Модерацию выполняйте на сервере, не доверяйте решению от браузера.
Go-обработчики, очередь ручной проверки и UI в этой задаче не изменены.

Для проверки откройте /docs после обычного запуска kb.api:app. Общий сервер при старте
по-прежнему загружает AnswerService/E5; отдельный импорт ModerationService этого не требует.
Тексты модерации не добавляются в FAQ и SQLite answer_requests; в технический журнал
идут только request_id/решение, без текста студента или ключей. Это не постоянный
журнал модераторских действий и не готовая очередь для admin-дашборда.

Unit/API-тесты используют заглушку LLM: проверяют контракт, валидацию и отказы, а не
точность классификации. До включения автопубликации оцените реальные примеры на трёх
языках, включая критику, цитаты оскорблений, угрозы и попытки обхода промпта.
Доступность указанной в .env модели gemini-3.8-flash и её качество пока не подтверждены.


## Исправление поиска и отображения ответов

`answer` — основной текст для студента на запрошенном языке. `forum_answer` —
оригинал подтверждённого источника (может быть на другом языке); не отображайте его
как основной ответ. При отказе модели/ошибке оба поля источника и forum_answer пусты.
`ai_explanation` теперь содержит полный ответ, а не только дополнение.
Поиск рассматривает до 1000 кандидатов в текущей небольшой базе, проверяет совпадение
терминов, сокращения и тип вопроса. Алиасы в kb/ranking.py ограничены несколькими
университетскими понятиями; это консервативная эвристика, не универсальный reranker.
Она может пропускать перефразировки/переводы и требует дальнейшей оценки.
При отсутствии подходящего FAQ AnswerService возвращает no_relevant_source без вызова
LLM, чтобы не выдумывать университетские факты. При сбое LLM возвращается HTTP 200,
status=fallback, reason=llm_overloaded/llm_unavailable и локализованное уведомление.
Это не успешный ответ на вопрос; клиент обязан учитывать status и reason.
Модерация по-прежнему возвращает ошибку и не разрешает публикацию при сбое провайдера.
